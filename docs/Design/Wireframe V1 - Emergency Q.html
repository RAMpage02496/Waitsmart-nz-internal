Version 1 proves the core interaction — list, search, select, view detail — before distance sorting, live updates or a map are added. Numbered pins map each component to the code that will build it.

1

Title header

A bold tk.Label at the top identifies the app. Static text only — sets the visual anchor for every later version.

2

Search bar — live filter (key component)

A tk.Entry bound to <KeyRelease>. On each keystroke, update_list() rebuilds the list showing only hospitals whose name contains the typed text (case-insensitive). This is the first real logic and the pattern the V2 distance-sort extends.

3

Hospital list + scrollbar

A scrollable tk.Listbox filled by iterating the HOSPITALS list of dictionaries. Selecting a row fires on_select(). The colour dot previews the green/amber/red wait status that becomes central in Version 2.

4

Selected hospital detail panel

A tk.LabelFrame holding four labels — name, type, wait time and phone — updated by on_select() for the highlighted hospital. Gives the user the full record without leaving the screen.
